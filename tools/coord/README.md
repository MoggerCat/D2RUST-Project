# tools/coord — multi-session build-loop tools

Tools for the coordinator and the cloud sessions merging into
`claude/specs-staging-7`. Python 3 stdlib and POSIX sh only. Every tool has a
`--selftest` (no game files, no network).

| Tool | Who runs it | What it does |
|---|---|---|
| `realdata.py` | coordinator gate, any session before a push | game-file (`#[ignore]`) tests vs `realdata-baseline.tsv`; fails only on a new failure |
| `playtable.py` | coordinator, after every staging push | `playthrough.py --all --json` → `docs/handoff/playability.md` (+/- milestones) |
| `sync.sh` | every session, every 20 minutes | merge staging into the current branch, auto-resolving the mechanical conflicts |
| `route.py` | coordinator, sessions | first-difference report → spec section, crate module, owner session |
| `union.py` | `sync.sh`, by hand | resolve append-only conflicts (both sides) or spec-index conflicts |
| `renum.py` | by hand during a merge | renumber an id only on lines the merge brings in |

## realdata.py

    D2_GAME_DIR=~/game python3 tools/coord/realdata.py                    # check
    D2_GAME_DIR=~/game python3 tools/coord/realdata.py -E 'test(/skill/)' # a subset
    D2_GAME_DIR=~/game python3 tools/coord/realdata.py --update-baseline  # on the staging head only

Runs `cargo nextest run -p d2-client -p d2-server -p d2-sim -p test-fixtures
--release --run-ignored only` (JUnit output, a 10-minute kill for hung
tests) and compares every test with `realdata-baseline.tsv` (`test<TAB>pass|fail`,
header names the head it was made on). Exit 1 only on a **new failure** (a
baseline pass that fails now, or a build failure); new passes, new tests and
tests gone are listed. The skip set of `tools/realdata-gate.sh` applies
(GPU, memory dump, repro, recording replays without `traces/raw/`, D2_SAVE
tests; `--no-skip` runs them). Speed: `CARGO_PROFILE_RELEASE_DEBUG=0` and
`CARGO_INCREMENTAL=0` (as `playthrough.py --build`), one shared `target/`.
Update the baseline only from a staging head, in its own commit. Needs
`cargo-nextest` (`cargo install cargo-nextest --locked`) and, for d2-client,
Bevy's system libraries (`tools/cloud-setup.sh`).

## playtable.py

    D2_GAME_DIR=~/game python3 tools/coord/playtable.py                 # current checkout
    D2_GAME_DIR=~/game python3 tools/coord/playtable.py --head origin/claude/specs-staging-7
    python3 tools/coord/playtable.py --from-json result.json --sha <commit>

Writes `docs/handoff/playability.md`: the head and time, per act reached /
total, consecutive, first blocker, the milestones gained and lost against the
previous table (kept in the file as a `playtable-data` comment) and a
30-row history. `--head` runs in a worktree at `target/coord-wt` sharing the
release build. Exit 1 when a milestone was lost.

## sync.sh

    sh tools/coord/sync.sh            # fetch origin/claude/specs-staging-7, merge it (never rebase)
    sh tools/coord/sync.sh --base B   # another base ($COORD_BASE works too)
    sh tools/coord/sync.sh --selftest # 11 cases on toy repositories

Auto-resolved: a spec conflict lying wholly inside its `<!-- index -->` table
(HEAD side, then `tools/spec_index.py`), `docs/handoff/provisional-index*.tsv`
(regenerated by `tools/provisional_index.py`), and the append-only
`docs/HANDOFF.md`, `docs/handoff/build-queue.tsv`, `docs/handoff/pc1-data.md`
(`union.py`: both sides, a line both added kept once). Any other conflict:
exit 1 with the merge left in progress and the files listed (the mechanical
ones already staged). The merge commit is refused while a conflict marker is
left in `docs/ specs/ crates/ tools/ facts/ traces/`. Refuses to start on a
dirty tree or mid-merge (exit 2).

## route.py

    python3 tools/coord/route.py traces/raw/check-x/state.summary.json
    python3 tools/scenario-diff/scenario_diff.py ... | python3 tools/coord/route.py
    python3 tools/coord/route.py --json result.json

Reads `state_diff` / `packets_diff` / `rng_diff` / facts-compare first
differences (text, `diff-summary-1`, `scenario-diff-result-1`) and playthrough
first blockers (text or `playthrough-result-1`). Field → spec from the Owner
column of `specs/tools/state-snapshot.md` §2; message → `specs/sim/client-messages.tsv`
/ `server-messages.tsv` row plus the specs naming that id; spec → module from
the `// Spec:` headers in `crates/` (non-test modules first); spec / module →
owner from `owners.tsv` (area, path prefixes, session, branch; the first
spec any row covers, longest prefix). Anything else prints `unrouted`; exit 1
when any line is unrouted.

`owners.tsv` is seeded from the 2026-10-09 day run in
`docs/handoff/overnight-loop.md`; the coordinator keeps it current.
