# q-tool-check-gen: hand-back (2026-10-09, branch `claude/q-tool-check-gen`)

`check-gen` (fidelity-gaps §4) is built: it writes the `.check` files of
the table-driven families under `traces/checks/gen/` from the live 1.14d
excel view. 683 checks + `INDEX.tsv`. The q-chk-* sessions can start now.

## What exists

| Piece | Path |
|---|---|
| generator | `tools/check-gen/check_gen.py` (`--check` = staleness, `--list`, `--family`, `--selftest`) |
| selftest (synthetic tables, no game files; real tables when `D2_GAME_DIR` is set) | `tools/check-gen/selftest.py` |
| shrine seed finder (runs d2rs) | `tools/check-gen/find_shrine_seeds.py` → `shrine-seeds.tsv` |
| d2rs-side smoke run | `tools/check-gen/d2rs_smoke.py` |
| inputs measured once | `tools/check-gen/waypoint-towns.tsv`, `shrine-seeds.tsv`, `ledger-areas.tsv` (ledger area ids = join key of the headers) |
| output | `traces/checks/gen/gen-<family>-<key>.check`, `INDEX.tsv` (name, family, table row, ledger area, title) |

Every file starts with `# GENERATED by tools/check-gen/check_gen.py (format 1),
family F, row R` and `# Ledger area: <area>`; never edit one, regenerate.

## Proof it runs

- `python3 tools/check-gen/check_gen.py --selftest`: every generated file
  parses with the strict `.check` parser of `scenario_diff.py`; a changed
  table row changes exactly its file; an edited or stray file makes
  `--check` fail; a missing column or an act outside 0..4 is an error.
- d2rs side (`d2rs_smoke.py --sample N`: every poke `ok`, run reaches the
  last tick): see the result block at the end of this file.
- Waypoint travel was verified end to end on d2rs for all five acts (the
  player's level changes to the target at frame 400+).

## Known limits and open points (all labelled, none hidden)

1. **Shrine rows are d2rs picks.** `poke object` creates a shrine whose
   row is rolled on the object control seed, which follows `-seed`.
   `find_shrine_seeds.py` searched d2rs for a seed per row; the `-seed`
   in the check is that seed. If 1.14d rolls another row for it, the first
   divergence is the shrine object's state at frame 30 (**PROVISIONAL REC-1330**: the
   control-seed derivation is d2rs's; settled by the first 1.14d run of
   any `gen-shrine-*`). Rows 0, 4, 5 and 16 are never picked by the init
   (`world/objects.md` §5.1 rule 4) so they have no check; they need
   preset objects 574–579, which `poke` cannot create (route: poke owner).
   Rows 2 and 3 use objects with `Parm0` 1 / 2 (deterministic).
2. **Skill casts have no target** (the `dru-*` pattern). Attack skills
   that need a monster, bow/javelin skills without the weapon, summons
   needing a corpse, auras and the 7 × passive skills per class produce an
   idle or refused click; the header says "Passive skill" for passives
   (flag `passive=1` in skills.txt). A second variant with a target (cow
   at +4, as `bar-whirlwind`) is a follow-up per skill the first run shows
   as inert.
3. **`wp` to a town waypoint** starts and ends in the same town (travel to
   itself); the town positions in `waypoint-towns.tsv` were measured on
   d2rs (`goto unit 2:<class>`), act 1's equals the 1.14d value
   (4899, 4209).
4. **`ai` takes the first class of an AI**: other classes of the same AI
   differ only in data, not code path; `monster.ai.none`, `.shadowmasternoinit`
   and `.provisional-points` of the ledger have no monstats row.
5. Level checks start from the act's town save, as the existing
   `a2-…a5-warp-*` checks; the spawn/skill families run in the Blood Moor
   under variant `blood-moor-empty` (needs the variant install on both
   sides, `tools/test-variants.md`).
6. Not generated (other tools, gaps §4): objects operate (interact-pokes),
   NPC menus, message families, item contents.

## Repro

```
export D2_GAME_DIR=$HOME/game          # live excel view built by session-setup
python3 tools/check-gen/check_gen.py            # regenerate (writes INDEX.tsv too)
python3 tools/check-gen/check_gen.py --check    # CI-style staleness check
python3 tools/check-gen/check_gen.py --selftest
cargo build --release -p d2-client -p d2s-tool
python3 tools/check-gen/d2rs_smoke.py --sample 4        # d2rs side, 4 per family
python3 tools/check-gen/find_shrine_seeds.py            # regenerates shrine-seeds.tsv
```

Ledger: `docs/handoff/ledger/q-tool-check-gen.tsv` (8 `coverage.check-gen.*`
rows, state NO-CHECK until a 1.14d comparison exists; validated with
`ledger.py` from `claude/q-fidelity-ledger`).
