# q-provisional-audit

Audit of the PROVISIONAL points (M22) without game files, 2026-10-08, branch
`claude/q-provisional-audit`. Method: every `PROVISIONAL` line of `specs/` and
`crates/` (430 hits: 77 in specs, 353 in crates) and every REC entry of
`docs/HANDOFF.md` §5/§7 (258 ids: 140 `- **REC-n**` bullets and `#####` headings
plus ids cited only from specs/crates), read for two points that assume
different things about one value, unit, order or owner; for code that differs
from the spec line it cites; and for a point a later merged spec contradicts.

## Files

- `docs/handoff/provisional-index.tsv`: one row per PROVISIONAL line (location,
  system, what was chosen, what settles it, `settle_kind` = recording / binary /
  data / unstated, `data_alone_may_settle`, `status` = already settled by a
  merged spec in `pc1-s8.md` and the queue row that carries the code fix).
  `rec` is the REC id on the line; `~REC-n` = no id on the line, the nearest
  one within 12 lines; `-` = none.
- `docs/handoff/provisional-index-rec.tsv`: one row per REC entry (HANDOFF line,
  tag, settle kind, whether data alone may settle it, duplicated id, how many
  PROVISIONAL points cite it, pc1-s8 status).
- Both are generated by `py tools/provisional_index.py` (keywords on the REC text; `settle_kind` and `data_alone` are a first sort,
  not a verdict: re-sort a row by hand when it matters). 88 lines state no
  settling capture at all (`unstated`); most are the `native-assets` / `ds1` /
  `automap` spec lines and code-only comments.

  `text-fonts.tsv`; classes 10097 Druid / 10098 Assassin as the REC-208 reading
  (`create.rs`).

- The 53-bit x87 reading is one shared assumption in five places
  (`vitals.md`, `treasure.md`, `pathing.md` §11.3, `stat-lists.md`, REC-21): it
  does not conflict, but one wrong answer breaks all five (see below).

## What real data settles first

The private repo's data (tables, MPQ contents, DS1/DT1/DC6, `Credits.txt`)
settles these without a recording. In order of cheapness; the first four are one
`data-tool` / `mpq-tool` command each.

1. **REC-208** class names 10097 / 10098: read `patchstring.tbl` of the
   installed `Patch_D2.mpq` (frontend-menus OQ).
2. **REC-220** loading art source: list `Patch_D2.mpq` / `d2exp.mpq` /
   `d2data.mpq` for `loading` DC6 (the PROVISIONAL says Patch_D2 was never
   probed by name).
3. **REC-185** credits row counts (1,231 / 1,797 of `frontend-credits.md` C4 r6)
   and the no-automatic-return claim: parse `Credits.txt`, `ExpansionCredits.txt`
   with the existing decoder.
4. **REC-259 / REC-249 / REC-261 / REC-230** and `q-fix-level-connections`: the
   real `Vis0–7` / `Warp0–7`, `lvlwarp.txt` and `lvlmaze.txt` rows replace the
   invented tree, ids and tile places (`data-tool tables`).
5. **REC-104 / REC-119 / REC-244** stash and cube grid corners: `inventory.bin`
   rows 9, 12 (expansion) and 8, 24 (classic) at 640 and 800 widths.
6. **REC-103 (4)** `gld` flippy name and direction count from `misc.txt` and the
   DC6 header.
7. **REC-157 / REC-101 / REC-137 / REC-140 / REC-144** `hireling.txt` rows (act
   of a list, names, skills, price, level) and **REC-137 / REC-140 / REC-144 /
   REC-280 / REC-278 (1) / REC-246 (b), (c)**: town and summit NPC / waypoint /
   object positions are DS1 preset units of the real files.
8. **REC-133 / REC-134 / REC-138 / REC-139 / REC-146 / REC-147**: the synthetic
   Act II / III / V sets are replaced by the real placer over the real tables
   (M23's play smoke on the install); each entry's "Needed" line is a local run
   on the user's files.
9. **REC-235 / REC-278 (2), (3) / REC-150 / REC-155 / REC-157 / REC-274**: made-up
   items, skills, hireling and charstats rows are replaced by `armor` / `weapons`
   / `misc` / `skills` / `monstats` / `charstats` / `itemstatcost` rows.
10. **REC-273 / REC-250 / REC-247**: `monstats2`, `leveldefs`, `Levels.txt` ambient
    columns for the unit facts and the light inputs.
11. Sound: **REC-19** (the 882 frames / 40 ms arithmetic) needs the real WAV
    headers (rate, channels, frame counts) for every sound the table names; the
    device behavior still needs the recording, but a wrong rate shows at once.
